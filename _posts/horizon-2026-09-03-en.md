## [Developer Ports 1993 Amiga Assembly Game to Godot Using LLM in One Evening](https://babyloniantwins.com/blog/porting-a-1993-amiga-game-to-godot/) ⭐️ 8.0/10

A developer ported his 1993 Amiga game, originally written in MC68000 assembly, to the Godot game engine in a single evening using an LLM (Claude) to read and translate the original code. He has made the original game free to download and published detailed, LLM-assisted notes about the process. This project shows that LLMs can meaningfully translate decades-old assembly code into modern game-engine logic, potentially making retro-game preservation and porting far more accessible. It may inspire a broader workflow where AI is used not just to explain legacy code, but to verify byte-level accuracy before rewriting it. The developer first had the LLM assemble the original code on a Mac using vasm, iterating until the resulting binary matched his original game files, except for a known 108-byte discrepancy. That mismatch arose because AsmOne, the 1993 assembler, assembled directly into memory, and the shipped game file was a snapshot of a running game rather than a clean assembler output.

hackernews · rabahs · Sep 3, 14:28 · [Discussion](https://news.ycombinator.com/item?id=49550375)

**Background**: The MC68000 is a Motorola CPU used in the Amiga, Atari ST, and early Macintosh systems, where game developers often wrote in assembly for speed and to fit tiny memory constraints. Godot is a modern, open-source game engine that provides high-level scripting, a scene system, and cross-platform support. Amiga developers of that era commonly used IDEs such as AsmOne or Devpac, while vasm is a modern portable and retargetable assembler able to recreate byte-identical binaries from old source code.

This simulation makes historical demographic ideas tangible for a broad audience, but inaccurate probability draws could mislead people about how human populations have changed over time. It also highlights the broader challenges of data-driven storytelling. The app reportedly generates details such as birth year, sex, marriage patterns, mortality, and other life events based on historical demographic sources. Community reviewers point out that birth years are not drawn from the correct probability distribution and that cited figures are internally inconsistent.

hackernews · thinkingemote · Sep 3, 14:51 · [Discussion](https://news.ycombinator.com/item?id=49550698)

**Background**: Estimates of the total number of humans who have ever lived typically use historical world population estimates and birth rates to sum births across time. Depending on assumptions, the total is commonly placed in the range of roughly 100 to 117 billion people. Because world population grew dramatically in recent centuries, a truly random draw from all ever-born humans should yield a birth year clustered near the modern era.
