It affects platform vendors, DevOps teams, and anyone managing secrets across container pipelines, reinforcing that leaked-credential exposure remains one of the most common and damaging attack vectors. The disclosure timeline ran from July 13 (initial report) to July 14, when Baseten's security contact acknowledged the critical issue, made the Harbor project private, rotated the token, and asked Strix to securely delete the pulled images.

## [GEFS checksumming copy-on-write filesystem gets early OpenBSD preview](https://marc.info/?l=openbsd-tech&m=178948744271633&w=2) ⭐️ 7.0/10

An early preview of GEFS — Ori Bernstein's checksumming, copy-on-write 'good enough' file system — has been posted to the OpenBSD tech mailing list, indicating initial porting work toward bringing it to OpenBSD. The announcement is accompanied by links to a EuroBSDCon 2026 talk and a recorded presentation, as well as reports from people already running GEFS on 9front. OpenBSD has historically lacked a modern checksumming, snapshot-capable file system of its own, so a proven implementation arriving from the Plan 9 world could meaningfully change storage options on that platform. Because GEFS has already been battle-tested in production on 9front, the port carries more credibility than a fresh experimental design and is likely to draw attention across the wider BSD and systems-programming community. GEFS is designed as a crash-safe, corruption-detecting, simple and fast snapshotting file system, in that order of priority; its block pointers carry a hash of the data they reference, so corruption from failing disks or file system bugs is detected and reported rather than silently propagated. A high-level FUSE 3 port of GEFS also exists, and the design is built around a snapshot tree that points to a number of file system trees.

hackernews · sippingabonedry · Sep 15, 17:12 · [Discussion](https://news.ycombinator.com/item?id=49715590)

**Background**: GEFS stands for 'Good Enough File System' and was originally built for Plan 9, the distributed research operating system created at Bell Labs by the same team behind Unix and C. 9front is a widely used fork of Plan 9 that continues to develop the system, adding things like WiFi support and new file systems, and GEFS has been running there long enough that 9front's nightly build machine now uses it. 'Copy-on-write' means new data is written to fresh blocks rather than overwriting existing ones, which enables cheap, consistent snapshots, while 'checksumming' means every block is hashed so that silent data corruption can be detected — the same combination popularized by ZFS and Btrfs on other Unix-like systems.
