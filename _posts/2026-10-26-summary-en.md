## [Anthropic Files S-1: $11.5B Quarterly Revenue and $500B+ in Compute Bets](https://www.sec.gov/Archives/edgar/data/2130357/000162828026067168/anthropicpbc-sx1.htm) ⭐️ 9.0/10

Anthropic filed its 355-page Form S-1 with the SEC on Monday, publicly disclosing for the first time that quarterly revenue jumped from $4.731B in Q1 2026 to $11.555B in Q2 2026 (roughly +144% quarter-over-quarter) and reached $16.8B in Q3 2026. The filing also reveals roughly $505B in multi-vendor compute commitments, including $114B to Google, $110B to AWS, $161B to Broadcom and $120B to SpaceX. The prospectus reports that Anthropic now generates about $2.08 in revenue for every $1 of compute spend, up sharply from $0.40 in Q1 2025 — implying a compute payback period of well under a year. ## [OpenAI claims academic collaborations produced major math, complexity, and physics results](https://openai.com/index/building-scientific-understanding-with-academic-communities/) ⭐️ 8.0/10

OpenAI published an announcement describing collaborative work with academic communities that it says produced three new discoveries: local smoothing and the Kakeya conjecture in harmonic analysis, the falsity of the Exponential Time Hypothesis in complexity theory, and the existence of quantum chromodynamics plus completions of the Standard Model in physics. If validated, these results would be major advances in mathematics, complexity theory, and physics and would strengthen the case that AI systems can contribute to frontier scientific discovery; they would also force a rethinking of ETH-based hardness assumptions. The claims are unusually broad for a single announcement, and the provided material does not include peer-reviewed proofs or independent verification; notably, falsifying ETH would not by itself prove P=NP, though it would overturn a widely used hardness assumption formulated by Impagliazzo and Paturi in 1999.

The Exponential Time Hypothesis (ETH) is the unproven assumption that solving 3-SAT requires time exponential in the number of variables, and it underpins many fine-grained complexity results. The Standard Model is a quantum field theory describing known elementary particles and their interactions, so 'completions of the Standard Model' refers to extending or completing that framework.

## [SIMD-Accelerated Computer Vision Runs on a $2 ESP32-S3 Microcontroller](https://shraiwi.com/blog/simd-fast-esp32s3/) ⭐️ 8.0/10

A developer blog post by shraiwi demonstrates SIMD-accelerated computer vision running on the ESP32-S3, a microcontroller that sells for roughly $2 in bare-chip form (and about $5.33 for a complete ESP32-S3-Zero board on AliExpress). Using the chip's vector instructions, the author reports a corner-detection throughput increase from 5.1 MP/s to 11.2 MP/s, or roughly 2.2× the scalar baseline. It shows that meaningful image processing — normally the domain of CPUs, GPUs, or dedicated accelerators — can run in real time on hardware costing a couple of dollars and a fraction of a watt, which matters for battery-powered sensors, robotics, and ultra-low-cost edge devices. The write-up also serves as a practical case study in squeezing SIMD out of an unusual embedded ISA rather than familiar x86 or Arm NEON. The ESP32-S3 is a dual-core Xtensa LX7 running at 240 MHz with 512 KB of internal SRAM and integrated 2.4 GHz Wi-Fi and Bluetooth 5 LE, built on a 40 nm process. Commenters noted that the author's "220% faster" phrasing is really a 120% increase (2.2× speedup), and that RISC-V alternatives such as the CH32V407/CH32V467 expose a much richer vector ISA with 64-bit SIMD width and LMUL register grouping for around $2.4 per unit.

hackernews · zdw · Oct 25, 22:29 · [Discussion](https://news.ycombinator.com/item?id=50236681)

**Background**: SIMD (Single Instruction, Multiple Data) is a parallel-computing technique in which one instruction operates on several data elements at once, which is why it speeds up pixel-wise image work so effectively. The ESP32-S3 is Espressif's Wi-Fi/Bluetooth microcontroller with a small set of vector instructions that most Arduino-style projects never touch. Computer vision on microcontrollers is normally limited to lightweight tasks such as edge and corner detection — the post's benchmark appears to center on the FAST (Features from Accelerated Segment Test) corner detector — because these devices have kilobytes, not gigabytes, of RAM.

## [Microsoft Proposes Type Server Protocol to Decouple Python Type Checkers from Editors](https://github.com/microsoft/pylance-release/blob/main/docs/tsp/type-server-protocol.md) ⭐️ 7.0/10

Microsoft published a specification for the Type Server Protocol (TSP), an open standard that extends the Language Server Protocol so that any editor or tool can plug in any Python type-checking engine as a first-class backend. The spec defines a type server that maintains type-analysis state for a workspace and answers requests for protocol version, snapshots, Python search paths, import resolution, and computed, declared, and expected types. Today a Python type checker is usually bolted onto a specific editor integration, so users are effectively locked into whichever engine ships with their IDE; TSP aims to make type checkers interchangeable the way language servers are, which could reshape competition between Pylance, Pyright, ty, Pyrefly and others. If adopted, it lowers the cost for new type-checking engines to reach editor users and gives developers real choice over the analysis behind their diagnostics. The protocol's TypeScript definition file notes that it is "Python specific at the moment, but may be made generic in the future," and all message types are designed to be JSON-serializable since they travel over the wire between the type server and a client such as a language server or IDE. Commenters observed that the result-type schema is deeply Python-shaped — for example it lacks a universal/forall binder — suggesting it will not be reused for other languages as-is.

hackernews · adamnemecek · Oct 26, 18:14 · [Discussion](https://news.ycombinator.com/item?id=50248371)

**Background**: The Language Server Protocol (LSP) is Microsoft's open, JSON-RPC-based standard that lets an editor talk to a language server for features like completion, go-to-definition and find-references, and it is why one editor can support dozens of languages. Static type checkers such as Pyright, Pylance, mypy, Astral's ty and Meta's Pyrefly analyze Python code without running it to catch type errors and power editor hints, but historically each one shipped its own editor integration glue. TSP proposes standardizing that glue layer — the boundary between a "type server" and its client — rather than adding more features to LSP itself.

## [33-Year-Old FreeCell Runs Unmodified on Windows 11](https://blog.enlyth.com/posts/oldest-windows-gui-app-win-11/) ⭐️ 6.0/10

A blogger investigating the oldest unmodified GUI application that still runs on Windows 11 identified FREECELL.EXE, dated 22-Feb-1993 and shipped with an early Win32s release, as the winner at roughly 33 years and 8 months old.
