## [Magic Hexagons Exist for Every Order via Potential Fields](https://gukov.dev/math/2026/08/02/new-magic-hexagons.html) ⭐️ 7.0/10

The article introduces an interactive exploration demonstrating that magic hexagons exist for every order n by using a potential-field construction method, extending beyond the classic n=1 and n=3 solutions. It includes interactive playgrounds that let readers experiment with the approach. This matters because it overturns the long-held belief that nontrivial magic hexagons exist only for order 3, opening up a new family of solutions. The potential-field technique offers an elegant, algorithmic way to construct these figures, which could inspire further work in recreational mathematics and computational design. The method defines a potential field on the hexagon cells and iteratively adjusts it to satisfy equal row sums, while also introducing a 'consecutive-no-duplicate' constraint. The author notes that even without these simplifying constraints, order 2 hexagons are impossible because fixing any side cell to a value x forces two other cells to sum to x.

hackernews · gukoff · Aug 9, 07:19 · [Discussion](https://news.ycombinator.com/item?id=49229174)

**Background**: A magic hexagon is an arrangement of numbers in a centered hexagonal grid where rows in all three directions sum to the same magic constant. A normal magic hexagon contains consecutive integers from 1 to 3n² − 3n + 1, and it has been mathematically proven that such normal magic hexagons exist only for n = 1 (trivial) and n = 3, the latter being the unique order-3 solution with magic sum 38. Potential field methods, originally from physics and later used in robotics for path planning, treat the desired outcome as a scalar field to be optimized; here the author adapts this idea to construct magic hexagons of arbitrary order.

## [Project Oberon Now Runs on RISC-V Instead of RISC-5](https://github.com/rochus-keller/OberonSystem/tree/op2-rv32) ⭐️ 6.0/10

A version of the Project Oberon System has been ported to run on the RISC-V instruction set architecture instead of the original RISC-5 CPU, targeting a low-cost Xilinx Spartan-3 FPGA board with 1 MB static RAM. The source is available on GitHub under the branch op2-rv32. This port makes the historically important Oberon system accessible on modern, open-standard RISC-V hardware, potentially extending its life and allowing a new generation to explore Wirth's design. It is incremental but contributes to the preservation and portability of classic system software. The port runs on a Digilent Xilinx Spartan-3 board with 1 MB of static RAM. It is not the first Oberon-on-RISC-V project; an earlier effort by solbjorg also exists. The original Oberon uses the RISC-5 architecture, a custom 32-bit RISC CPU, not RISC-V.

hackernews · Rochus · Aug 9, 12:43 · [Discussion](https://news.ycombinator.com/item?id=49230891)

**Background**: Project Oberon is a complete desktop computer system designed by Niklaus Wirth and Jürg Gutknecht in the late 1980s, written almost entirely in the Oberon language and documented in the book 'Project Oberon'. The system was originally implemented on a custom processor, RISC-5, used in the 2013 FPGA version. RISC-V, in contrast, is a free and open-standard ISA developed at UC Berkeley, now maintained by RISC-V International, and is widely used in microcontrollers and embedded systems. Porting Oberon to RISC-V allows it to run on widely available, low-cost hardware rather than the niche RISC-5 architecture.
